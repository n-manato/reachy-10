# 機体ごとの実測値

このディレクトリの `<robot_id>.yaml` は **測って入れる値**だけを置く場所。
無ければ `Calibration` が既定値（`audio_lead_ms: 0.0`）で動くので、
ファイルが無いこと自体はエラーにならない ―― だからこそ、**入っていないのに
入っているつもりになりやすい**。現状を `orchestra calibrate show` で確認できる。

## audio_lead_ms — なぜ必要になったか

物理楽器があった頃、これは飾りだった。音はビーターが楽器を叩いた瞬間に出るので、
モーションが揃えば音も揃う。楽器を外した今は**音声再生の揃い方が音楽そのもの**で、
モーションは見た目を合わせる役に降りた。ずれる余地が新しくできた。

ソフト側で分かっている分はすでに引いてある:

- GStreamer がパイプラインの遅延として **286.0 ms** を報告し（9台とも同値）、
  `AudioStream.schedule` がこれを PTS から差し引く
- 音声もモーションも**同じ `t0_monotonic`** を基準にしている
  （`agent/orchestra_agent.py` の `_play` が sleep する時刻と同じ値）

残るのは、その先の**機体ごとの物理的な差**。DAC・アンプ・スピーカーの個体差と、
サーボが指令を受けてから実際に動くまでの遅れの差。これは計算で出せないので、
測るしかない。

## 測り方

1. 1台だけ、打点のはっきりしたパートで演奏させる（ウッドブロックが最も読みやすい）

   ```
   orchestra show run small_world --robot r06
   ```

2. スマートフォンなどでその1台を**動画で**撮る。音と映像が同じファイルに
   入っていることが重要 ―― 別々に録ると、その2つのずれを測る羽目になる。

3. 波形の立ち上がりと、映像で頭が最下点に達したコマを突き合わせる。
   - 音が**先**なら `audio_lead_ms` は**負**（音を遅らせる）
   - 音が**後**なら**正**（音を早める）

4. 書き込む:

   ```
   orchestra calibrate audio --robot r06 --lead-ms -12.5
   orchestra calibrate show
   ```

5. 9台分繰り返す。値がどれも似た数字なら、それは共通の系統誤差なので
   `fleet.yaml` 側に1つ置くほうが正しい。**ばらついたときだけ**ここが効く。
